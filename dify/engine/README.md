# 斗地主残局引擎

纯标准库实现，无第三方依赖。既可本地跑单测，也能整块粘进 Dify 的「代码执行」节点。

## 文件

| 文件 | 用途 |
|---|---|
| `doudizhu.py` | 引擎：牌型判定、比大小、走子生成、AI、对局推进、求解器 |
| `puzzles.json` | 20 个残局关卡（含标准解与提示） |
| `make_puzzles.py` | 重新生成关卡（构造 + 求解验证） |
| `test_doudizhu.py` | 20 条单测 |
| `build_dify_node.py` | 把引擎 + 关卡打包成 `dify_node.py` |
| `dify_node.py` | **要粘进 Dify 代码节点的文件**（约 30KB / 835 行） |

## 本地跑

```bash
python -m unittest -v          # 20 条测试
python make_puzzles.py         # 重新生成 puzzles.json（约 3 秒）
python build_dify_node.py      # 生成 dify_node.py
```

## 牌面与输入

- 牌面：`3 4 5 6 7 8 9 T(10) J Q K A 2 x(小王) X(大王)`
- 玩家输入：`34567`、`3 3 3 4`、`10 J Q K A`、`过`、`提示`、`认输`
- 指令：`下一关` / `重开` 由 Dify 节点入口处理

## 接入 Dify 代码节点

节点类型：**代码执行（Python3）**，把 `dify_node.py` 全文粘进去。

输入变量（三个都要建）：

| 变量 | 来源 | 说明 |
|---|---|---|
| `state` | 会话变量 `game_state` | 首次为空字符串 |
| `move` | `sys.query` | 玩家这一句 |
| `level` | 会话变量 `level`（数字，默认 1） | 关卡号 |

输出（在节点里直接 `return`，Dify 会解析成变量）：

| 变量 | 用途 |
|---|---|
| `ok` | 本次输入是否合法 |
| `message` | 牌桌文本（手牌 / 剩牌 / 上家出牌 / 结果） |
| `state` | 新的牌局 JSON，**必须写回会话变量 `game_state`** |
| `status` | `playing` / `win` / `lose` |
| `steps_left` | 剩余步数 |
| `level` | 当前关卡号 |
| `title` | 关卡标题 |

写回会话变量用「变量赋值」节点：`game_state = 代码节点.state`、`level = 代码节点.level`。

## 关卡数据

每个关卡：

```json
{
  "id": "p01",
  "title": "第 1 关 · 顺子开路",
  "seats": 2,
  "steps": 2,
  "names": ["你", "左家"],
  "hands": [["3","3","5","6","7","8","9"], ["3","4","5"]],
  "solution": [["5","6","7","8","9"], ["3","3"]],
  "hint": "先出 5 6 7 8 9",
  "tags": ["straight"]
}
```

- `steps` = 标准解长度，也就是「几步内必须出完」。
- `solution` 是求解器在**确定性 AI** 下算出来的，单测里有一条用例会把它重新跑一遍，必须真的赢。
- 关卡是生成器构造的，想改难度直接改 `puzzles.json`（改完跑一次单测就知道还解不解得开）。

## 已知限制

- AI 只做「最小合法牌 + 快输时压大」的启发式，不是强 AI；残局的难度来自步数限制和牌型组合。
- 只做残局，不含发牌、叫地主、倍数、春天。
- 求解器带节点预算（默认 20 万），极端牌型可能返回「无解」，此时提示文案会兜底。
- `dify_node.py` 约 30KB；如果你的 Dify 代码节点有大小限制，把 `PUZZLES` 拆到另一个节点再传进来。

## 1. 技术分工（先想清楚，再动手）

| 技术 | 承担 | 不承担 | 评审怎么核对 |
|---|---|---|---|
| **Dify**（必选） | 每回合全部编排：规则引擎（代码节点）、知识检索、LLM 对白、记忆读写、回复 | 不持久化牌局（存会话变量） | 工作流运行详情逐节点可见 |
| **PowerContext** | 玩家档案：卡在哪关、怎么输的、通关记录，跨会话复用 | 不存牌局状态 | Dashboard + `/v1/atomic-memory/list` |
| **seekdb** | Dify 知识库的向量存储：残局讲解、牌型速查、对白素材 | 不存玩家记忆 | `SHOW TABLES` + `COUNT(*)` |

> 规则是"seekdb、PowerContext **至少一种**"。本作两个都用；若 seekdb 死活起不来，把 `VECTOR_STORE` 改回 `weaviate`，知识库改静态提示词，**仍然合规**，只是少一个加分点。

## 2. 第 1 步：验证 Dify + seekdb（现在做）

```bash
cd ~/workspace/dify/docker

# 1) 容器状态：应该 9 个服务全部 Up / healthy
docker compose -f docker-compose.yaml -f docker-compose.seekdb.yaml ps

# 2) seekdb 日志：等它打完初始化
docker logs seekdb --tail 30

# 3) 建库（Dify 的知识库表会建在这个库里）
docker exec -it seekdb mysql -h127.0.0.1 -P2881 -uroot -pseekdb123 \
  -e "CREATE DATABASE IF NOT EXISTS dify; SHOW DATABASES;"

# 4) 确认版本
docker exec seekdb mysql -h127.0.0.1 -P2881 -uroot -pseekdb123 -e "SELECT VERSION();"

# 5) 确认 Web 通了
curl -I http://localhost:8080
```

**通过标准**：`ps` 里 `api / worker / web / db / redis / nginx / sandbox / plugin_daemon / seekdb` 都是 `Up`（部分显示 `healthy`）；建库命令返回 `dify`；`curl` 返回 `HTTP/1.1 200`。

### 排错

| 现象 | 处理 |
|---|---|
| `seekdb` 反复 `Restarting` | `docker logs seekdb --tail 100`；多半是 `MEMORY_LIMIT` 太小或 `volumes/seekdb` 权限 |
| `api` 起来又挂 | 先修 seekdb，api 会自动重连；`docker logs docker-api-1 --tail 50` |
| 8080 被占 | 改 `.env` 的 `EXPOSE_NGINX_PORT`，再 `up -d` 重建 nginx |
| 密码连不上 | 试空密码 `-uroot`；能连就 `ALTER USER 'root'@'%' IDENTIFIED BY 'seekdb123';` |
| 拉镜像卡住 | 等；或配 registry mirror 后重试 |

> 用硅基流动也行：Base URL `https://api.siliconflow.cn/v1`，模型 `BAAI/bge-m3`，维度 1024。

### 3.4 自检

设置 → 模型供应商，两个都显示「已配置」；随便建个空白应用发一句话，能回就说明模型通了。

## 5. 第 4 步：装 PowerContext（WSL 原生，不用 Docker）

### 5.1 安装

```bash
sudo apt install -y python3-venv git
curl -LsSf https://astral.sh/uv/install.sh | sh
export PATH="$HOME/.local/bin:$PATH"
echo 'export PATH="$HOME/.local/bin:$PATH"' >> ~/.bashrc

uv tool install --force "powercontext[cli,server]==1.4.1"
powercontext --version
```

### 5.2 初始化

```bash
mkdir -p ~/pc && cd ~/pc
powercontext config init --language zh --output .env
```

向导选择：

| 问题 | 选 | 原因 |
|---|---|---|
| 存储 | SQLite | 最稳；seekdb 的角色留给知识库 |
| 使用场景 | 允许其他机器/容器访问 | Dify 在 Docker 里 |
| 记忆能力 | 自定义，只开 Embedding | 显式写入，不需要自动抽取；中文召回要向量 |
| Dashboard | 开启 | 截图证据 |
| 认证 | 关闭 | 避免 token 进 DSL |

### 5.3 改 `.env` 并启动

```bash
cd ~/pc
cat >> .env <<'EOF'

POWERCONTEXT_SERVER_HTTP_HOST=0.0.0.0
POWERCONTEXT_SERVER_HTTP_PORT=8000
POWERCONTEXT_SERVER_DASHBOARD_ENABLED=true
POWERCONTEXT_SERVER_ALLOW_UNAUTHENTICATED_NON_LOOPBACK=true
POWERCONTEXT_SERVER_RUNTIME_MEMORY_EXTRACTION_PROFILE=conversation
EOF

powercontext config validate --env-file .env
powercontext server run --env-file .env
```

保持这个终端开着。另开一个终端验证：

```bash
curl -fsS http://127.0.0.1:8000/health/live
curl -fsS http://127.0.0.1:8000/health/ready
```

### 5.4 让 Dify 容器能访问

```bash
ip -4 addr show docker0 | grep inet          # 记下 172.17.0.1
docker exec docker-api-1 python -c "import urllib.request;print(urllib.request.urlopen('http://172.17.0.1:8000/health/live').status)"
```

返回 `200` 就通了。后面 Dify 里的 `PC_BASE_URL` 就填 `http://172.17.0.1:8000`。

### 5.5 跑通记忆闭环

```bash
PC=http://127.0.0.1:8000

curl -s -X POST $PC/v1/scopes -H 'Content-Type: application/json' \
  -d '{"title":"ddz-test","summary":"测试存档","idempotency_key":"ddz-test"}'
# 记下返回的 scope_id

curl -s -X POST $PC/v1/memory/remember -H 'Content-Type: application/json' \
  -d '{"scope_id":"<SCOPE>","kind":"event","text":"第 6 关 五张连珠：失败（3 步预算，用了 3 步）","reason":"牌局结算"}'

curl -s -X POST $PC/v1/context/prepare -H 'Content-Type: application/json' \
  -d '{"scope_id":"<SCOPE>","query":"第 6 关 失败","max_bytes":3000}'
```

`prepare` 返回 `status=ready` 且 `content` 里有上面那句，说明中文召回可用。

## 6. 第 5 步：搭 Chatflow

### 6.1 建应用

**工作室 → 创建空白应用 → Chatflow**，命名「斗地主 · 读心牌桌」。

### 6.2 变量

**会话变量**（编排页的「变量」入口 → 会话变量）：

| 变量 | 类型 | 默认值 |
|---|---|---|
| `game_state` | 字符串 | 空 |
| `level` | 数字 | 1 |
| `player_key` | 字符串 | 空 |

**环境变量**：

| 变量 | 值 |
|---|---|
| `PC_BASE_URL` | `http://172.17.0.1:8000` |

### 6.3 节点表

| # | 节点 | 类型 | 配置 | 输出 |
|---|---|---|---|---|
| 1 | 开始 | 开始 | 变量 `玩家ID`（文本，选填） | `sys.query` / `sys.user_id` |
| 2 | 身份 | 代码执行 | 见 6.4 | `player_key` |
| 3 | 取存档 | HTTP 请求 | `POST {{#env.PC_BASE_URL#}}/v1/scopes` | `body.scope_id` |
| 4 | 引擎 | 代码执行 | 粘 `dify_node.py`，见 6.5 | 9 个字段 |
| 5 | 写回 | 变量赋值 | `game_state`←引擎.state，`level`←引擎.level，`player_key`←身份.player_key | — |
| 6 | 召回 | HTTP 请求 | `POST .../v1/context/prepare` | `body.content` |
| 7 | 讲解 | 知识检索 | 残局讲解库，TopK 2 | `result` |
| 8 | 对白 | LLM | 见 6.7 | `text` |
| 9 | 是否结算 | 条件分支 | `{{#引擎.settled#}}` 为 true | — |
| 10 | 写记忆 | HTTP（true 分支） | `POST .../v1/memory/remember` | — |
| 11 | 汇合 | 变量聚合器 | 合并两分支 | — |
| 12 | 输出 | 模板转换 | 见 6.9 | `text` |
| 13 | 回复 | 直接回复 | `{{#输出.text#}}` | — |

连线：`1→2→3→4→5→6→7→8→9`，`9(true)→10→11`，`9(false)→11`，`11→12→13`。

### 6.4 代码·身份

输入：`玩家ID`（开始节点）、`uid`（`sys.user_id`）。输出 `player_key`。

```python
import re

def main(玩家ID: str, uid: str) -> dict:
    name = (玩家ID or "").strip() or (uid or "").strip() or "guest"
    key = re.sub(r"[^0-9A-Za-z_\-\u4e00-\u9fa5]", "", name)[:24] or "guest"
    return {"player_key": "ddz-" + key}
```

### 6.5 代码·引擎（核心）

把 `~/workspace/ddz/engine/dify_node.py`（Windows 路径 `...\dify\engine\dify_node.py`）**全文**粘进「代码执行」节点（Python3）。

三个输入变量必须**同名**：

| 输入 | 值 |
|---|---|
| `state` | `{{#conversation.game_state#}}` |
| `move` | `{{#sys.query#}}` |
| `level` | `{{#conversation.level#}}` |

输出：`ok / message / state / status / steps_left / level / title / settled / summary`。

> 首次 `game_state` 为空串，节点自动开第 1 关。

### 6.6 HTTP 节点

**取存档**

```
POST {{#env.PC_BASE_URL#}}/v1/scopes
{"title":"{{#身份.player_key#}}","summary":"斗地主读心牌桌 玩家存档","idempotency_key":"{{#身份.player_key#}}"}
```

**召回记忆**

```
POST {{#env.PC_BASE_URL#}}/v1/context/prepare
{"scope_id":"{{#取存档.body.scope_id#}}","query":"{{#sys.query#}} {{#引擎.title#}}","max_bytes":3000}
```

**写记忆**（条件分支 true 分支）

```
POST {{#env.PC_BASE_URL#}}/v1/memory/remember
{"scope_id":"{{#取存档.body.scope_id#}}","kind":"event","text":"{{#引擎.summary#}}","reason":"牌局结算"}
```

三个 HTTP 节点都设：超时 15s、重试 2 次、**异常处理 = 继续执行并给默认值**（空字符串）。

### 6.7 LLM·对白

**System**

```
你是斗地主残局牌桌上的两个看客，只负责说话，不负责打牌。

角色：
- 老K（左家）：四十岁，跑江湖的老油条，说话慢、阴阳怪气，爱提旧账。
- 小七（右家）：二十出头，莽撞咋呼（只有三人关才有他）。

铁律：
1. 牌局结果、手牌、胜负全部以「牌桌」为准，不得修改、不得编造牌。
2. 不要复述牌桌信息，不要解释规则，不要给建议——除非玩家明确问「怎么打 / 提示」。
3. 玩家出错牌被系统拒绝时，只调侃，不能替他改牌。
4. 「旧战绩」里有内容时必须具体提起（哪一关、怎么输的）。
5. 「讲解素材」只用来支撑解说，不要照抄。
6. 输出 2–3 句，每句不超过 40 字，用「老K：」「小七：」开头。

旧战绩（可能为空）：
{{#召回.body.content#}}

讲解素材（可能为空）：
{{#讲解.result#}}
```

**User**

```
牌桌：
{{#引擎.message#}}

玩家刚说：{{#sys.query#}}
```

模型 `deepseek-chat`，temperature 0.8，max tokens 300。

### 6.8 条件分支与汇合

- 条件：`{{#引擎.settled#}}` `is` `true`
- true → 写记忆 HTTP → 变量聚合器
- false → 变量聚合器
- 聚合器输出接模板

### 6.9 输出模板

```
{{#引擎.message#}}

{{#对白.text#}}
```

### 6.10 联调顺序（不要一次全连）

1. `1→2→3→4→13`：能开局、能出牌、能看牌桌
2. 接 `5`：刷新页面牌局还在（会话变量生效）

## 9. 排错速查

| 症状 | 原因 | 解法 |
|---|---|---|
| `docker compose` 不认 | 缺插件 | `sudo apt install -y docker-compose-v2` |

### 1.2 出题与判分

**测试概念**：`伪共享`

**生成的题目**：
> 在编写并行程序前，为什么需要首先明确目标机器的内存模型是共享内存还是分布式内存？

**学习者答案**：
> 因为内存模型直接决定并行程序的编程模型、数据组织、通信与同步方式。共享内存中所有线程可访问同一地址空间，重点是用线程/OpenMP、锁和原子操作处理竞争、缓存一致性与伪共享；分布式内存中各进程有独立地址空间，必须显式划分数据并通过消息传递（如MPI）通信和同步。若未先明确，可能选错编程模型、遗漏通信/同步、造成数据竞争或性能不可移植。因此先明确内存模型，才能正确设计数据分布、通信模式和同步策略。

**判分结果**：
- ✅ **正确**
- 反馈：答案准确涵盖了参考答案的核心内容，包括内存模型对编程模型的影响、两种内存模型的关键区别、以及不明确内存模型的后果
- **记忆写入**：✅ 成功（PowerContext 已接入）

## 四、技术亮点

### 4.1 一条 SQL 完成混合检索

```sql
WITH vec AS (
  SELECT id, l2_distance(emb, %(qvec)s) AS dist
  FROM chunks WHERE ... ORDER BY dist APPROXIMATE LIMIT 40
),
ft AS (
  SELECT id, MATCH(content) AGAINST(%(qseg)s) AS fts
  FROM chunks WHERE MATCH(content) AGAINST(%(qseg)s) ...
),
...
SELECT ... ORDER BY fused DESC LIMIT 3;
```

**优势**：
- 向量 + 全文 + 标量过滤在一条 SQL 内完成
- RRF 融合（k=60）平衡两支路
- 标量过滤写在子查询内部，避免 ANN 退化

### 4.2 PowerContext 记忆闭环

```
出题 → 答题 → 判分 → 写记忆 → 读弱点 → 优先出题
```

**关键设计**：
- 每学习者一个 scope，惰性创建
- 状态机：新学 → 巩固 → 掌握（连对 3 次）
- 答错重置为"新学"，count+1

### 4.3 语料质量管控

- `review_status` 字段标记可疑内容
- 3 处语料硬伤已修正（Amdahl 表格、Allreduce 通信量、MPI_SUM 大小写）
- 出题时自动排除 `review_status='excluded'` 的切片

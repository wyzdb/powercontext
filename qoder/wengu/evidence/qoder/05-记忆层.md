## 本轮目标

PowerContext 的得分点全在"跨会话"三个字上。这一轮的验收脚本要能排除"假记忆"。

## Qoder 对话要点

### 提示词核心内容

```
【目标】
产出 app/memory.py + scripts/memory_demo.py：
1. scope 粒度 learner:<id>，一个学习者一个 scope
2. 记忆条目结构：{type, concept, evidence, count, status, last_seen}
3. 封装四个函数：get_profile / upsert_weakness / advance_progress / get_review_plan
4. 写入走显式 API；写入前先读同 concept 去重
5. scripts/memory_demo.py 演示跨会话

【约束】
- 不许把记忆缓存到本地文件或内存里冒充
- 网络失败要重试 + 幂等
- PC 不可用时，接口要返回明确降级提示
```

### Qoder 完成的工作

1. **Scope 管理**：按 learner 惰性创建 scope，用 idempotency_key 保证幂等
2. **记忆编码**：结构化 JSON 前缀 `[[wengu]]` 标记，存在 text 字段
3. **去重逻辑**：同一 concept 的多条记录只认 count 最大的那条
4. **降级处理**：PC 不可用时返回 `source: "unavailable"`

### 关键产出

- `app/memory.py`：193 行 PowerContext 客户端
- 4 个核心函数：`get_profile`, `upsert_weakness`, `advance_progress`, `get_entries`

### 实测结果

**跨会话验证**
```
进程 A：给 learner=demo 写 3 条弱点
  → weakness: 伪共享 (count=1)
  → weakness: 缓存一致性 (count=1)
  → weakness: 死锁 (count=1)

进程 B：全新启动，读回
  → recalled 3 weaknesses: 伪共享 (x1), 缓存一致性 (x1), 死锁 (x1)
  → 证明是从 PowerContext 读的，不是本地缓存
```

**服务不可用降级**
```
把 PC 服务停掉再跑 → 明确报"记忆服务不可用"，不是崩栈
→ /api/profile 返回 source: "unavailable"
```

## 踩坑记录

**问题**：PowerContext 端点路径与文档不符

**实测真实 API**（2026-10-28）：
- 建 scope：`POST /v1/scopes` → `{title, summary, idempotency_key}` → 返回 `scope_id`
- 写记忆：`POST /v1/memory/remember` → `{scope_id, kind, text}`
- 列记忆：`POST /v1/memory/entries/list` → `{scope_id}` → `{entries:[...]}`
- 召回：`POST /v1/context/prepare` → `{scope_id, query}`

**关键发现**：
- scope 由服务端生成，不能自带
- 请求体字段是 `text` + `kind`（不是 `content`）
- `app/memory.py` 顶部 4 个常量隔离设计奏效——只改了这一个文件

**设计原则**：
> 绝不因 PC 不可用而把记忆兜底写进 seekdb。宁可这一题没记住，也不能让状态回到两个系统里。

1我这轮的提示词
【目标】产出 app/main.py（FastAPI）+ web/index.html（单页，纯 HTML+fetch，不要 npm）：
  1. POST /api/ask {learner, query} → 调 app.retrieval.search，把命中变成可展开的引用卡片
  2. GET /api/profile/{learner} → 先返回假数据，第 5 轮再接 PowerContext
  3. 页面三个区：提问 / 今日复习 / 我的弱点
  4. 出题 + 判分端点

【约束】
- 回答必须带出处，无出处的结论不许输出；资料里没有就直说「资料中未提及」，不许编
- 统一错误结构 {code, message}，不要把 stack trace 返回给前端
- 冷启动一条命令：uvicorn app.main:app，评审机器不许装构建工具
- 不许改 app/ingest.py、app/retrieval.py、docs/、data/

【验收】提问「死锁」能返回带出处的三条结果

5本轮踩坑与遗留
  • Decimal 把响应炸了：SQL 里的 fused 是 DECIMAL，starlette 默认 json.dumps 不认 → 显式 float()。
  • retrieval.connect() 返回 DictCursor：我按 row[0] 取值直接 KeyError，改成 row["doc_id"]。
  • 导入顺序是隐式契约：DIM/PROVIDER 在 app.embed 里是导入期定值，所以 load_env_file() 必须排在 from app.retrieval import … 之前，并在代码里写了注释钉住这条。
  • 出题偶发退回模板：模型限流时降级为「请简述 XXX 的核心内容」，同时把 llm_used:false 如实返回，不伪造调用成功。
  • 遗留：前端今日区读 data.review_plan / w.concept_name，而 /api/profile 目前只返回 weaknesses[].concept，字段没对齐 —— 今日复习区会走 catch 显示「读档案失败」，第 7 轮的清单口径要连同 get_review_plan 一起补。

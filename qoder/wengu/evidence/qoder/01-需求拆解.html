【背景】
data/raw/ 下是 6 篇并行计算讲义（markdown，带 YAML front matter），约 1.27 万字、23 个 ## 小节。
先把这些文件逐篇读一遍，统计：主题覆盖、概念重叠（比如「伪共享」在体系结构和 OpenMP 两篇都出现）、
每个小节适合出什么类型的题、哪些概念之间存在前置依赖。

【目标】
只写文档，一行代码都不要写。产出 docs/01-需求与方案.md，必须包含 6 节：
  1. 用户与场景   —— 痛要点具体到「考前 3 天翻十几份笔记」这种颗粒度，不要写"提高效率"
  2. 功能边界     —— 做哪 4 件事、明确不做什么
  3. 技术分工表   —— seekdb 和 PowerContext 的分工必须互斥且互补
  4. 数据模型     —— seekdb 建表语句 + PowerContext 的 scope 粒度与记忆条目 JSON
  5. 主流程时序   —— 文字箭头画出数据在哪一步流经哪个组件
  6. 风险清单     —— 至少 5 条，每条给一个具体规避动作

【约束】
- 表结构必须支撑「向量 + 全文 + 标量过滤」在一条 SQL 里完成混合检索
- 记忆必须是显式写入（我们主动调 API 写），不依赖模型自动抽取
- 每个功能都要能对应到一张表或一个端点，对不上的功能就砍掉

【验收】
- 拿着第 4 节能直接建表，不需要再问任何问题
- 第 3 节的表里没有「既存文档又存记忆」的模糊地带

§3 技术分工表（互斥性是全项目的锚）docs/01:96-106
| seekdb       | 9 张表：切片正文与向量、概念、题目、答题记录
|              | 查：一条 SQL 完成向量+全文+标量过滤融合排序
|              | 不存用户状态（弱点/进度/偏好）
| PowerContext | 每学习者一个 scope 的 weakness / progress / preference
|              | 查：出题前弱点排序、判分后写回、跨会话画像
|              | 不存正文、不存向量、不做全文检索
| LLM          | 只出题、判分、讲解；不负责检索与记忆

**一句话分工**：seekdb 记得「资料说了什么」，
            PowerContext 记得「你哪里不会」。

4本轮定下来的关键决策
  • 状态机只有三档：新学 → 巩固 → 掌握，「错 1 次回退到新学、count+1」，明确禁止自己加档位（§4.7.2）。
  • 显式写入记忆：不调 PC 就什么都不记；宁可这一题没记住，也不让状态散到两个系统里。
  • 语料不是干净的：勘察发现讲义自带 3 处硬伤（Amdahl 表 4.7→5.93、Allreduce 数据量口径、MPI_Sum 大小写），于是数据模型里预留 review_status/review_note，suspect 块可讲解但禁止出计算题。
  • 受控概念词表 40 条 + 前置依赖边：写进 §4.8 / §4.9，出题与推荐顺序都靠它，不让 LLM 自由发挥造概念。
  • 砍掉的功能：不做学习路径规划、不做多租户账号体系、不做讲义编辑 —— 找不到对应的表或端点，按约束直接砍。

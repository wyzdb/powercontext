    return data["records"][0]["artifact"]["artifact_id"]

5本轮踩坑与遗留
  • 端点全是猜的，猜错了：按 §4.7.3 推测的 /scopes/{learner}/memories 一律 404。逐个打真服务才拿到 /v1/scopes、/v1/memory/remember、/v1/memory/entries/list；字段是 text + kind，不是 content/type。
  • 服务端没有 update，也没有去重：字节完全相同的 text 连写两次，两次 changed:true。所以「count+1」只能是追加 + 读侧取最大，「不翻倍」是逻辑上的收敛而不是物理上不新增。
  • idempotency_key 是有条件的：同 key + 同参数 → 返回同一个 scope_id；同 key + 改了 title/summary → 409 scope_idempotency_conflict（今日实测）。所以文案不能随便改。
  • 非结构化条目要显式报数：scope 里混着手工种子文本，若无条件采信会把「以为加了 critical 就能解决伪共享」当成弱点档案。现在的处理是不计入 + note 里说清几条没采信。
  • 遗留（不掩饰）：① get_review_plan(learner, days) 未实现，今日清单靠 profile 的 count 排序；② entries/list 的分页 next_cursor 未跟随，长历史会截断；③ data/pc_scopes.json 本地缓存在 CLI 入口会盖掉 PC_SCOPE_ID（load_env() 在 _post() 内才执行，读 override 时 .env 还没进环境），与「禁止第三种存储」的精神相冲，应删。

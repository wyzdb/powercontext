1我这轮的提示词
【目标】把资料变成可检索的库：
  1. 读 data/raw/ 全部 md：解析 front matter，按 ## 小节切片
  2. 每块额外抽三个标量字段：topic、level、has_code（后面一条 SQL 的 WHERE 全靠它们）
  3. 批量调 embedding，失败要重试
  4. 建表 chunks：同时含向量索引和全文索引
  5. 幂等：可重复跑，不产生重复切片
  6. 结束打印统计行

【约束】
- 写表前校验 embedding 实际维度与表定义一致
- 只导入 data/raw/；data/local/ 是私有目录，不许进代码、库、日志
- 中文全文检索要能正确分词
- 向量 + 全文必须在同一张表上，否则一条 SQL 做不了混合检索

【验收】行数 == 切片数；增量重跑不翻倍；「伪共享」全文命中数 > 0

4本轮踩坑
  • 中文全文查不到：一开始用 IN BOOLEAN MODE，命中恒为 0。ngram 分词器只在自然语言模式下把查询串切成 bigram，改回 MATCH … AGAINST(q) 后命中 7 条。已写进 docs/01 §4.10 实测校正。
  • content_seg 预分词列是多余的：实测 TOKENIZE('伪共享指两个线程','ngram') 切分本来就对，预分词再交给 ngram 是双重分词。全文索引改建在 content 上；列本身留着但不再被索引，ingest 写入的是与 content 相同的值。
  • 哈希向量拉不开差距：均匀加权的 bigram 哈希让「伪共享」和「共享内存」近似。改成 TF-IDF 加权后离线也能排序，评审机器没 Key 也能跑。
  • 维度校验必须前置：EMB_DIM 从 .env 读，写库前比对首条向量长度；向量列建好就改不了，错一维整库废。
  • 统计口径瑕疵：日志里的「概念关联 N 条」是 INSERT IGNORE 的尝试数，落库数以 chunk_concept 实际行数为准（今日 23 行）。对不上时以库为准。

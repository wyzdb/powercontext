## 本轮目标

把资料变成可检索的库。这一轮的质量直接决定后面检索准不准。

## Qoder 对话要点

### 提示词核心内容

```
【目标】
产出 scripts/ingest.py + app/schema.py：
1. 读 data/raw/ 下全部 md：解析 front matter，按 ## 小节切片
2. 每块额外抽三个标量字段：topic、level、has_code
3. 批量调 embedding（batch=16，失败重试 3 次）
4. 建表 chunks：含向量索引和全文索引
5. 幂等：--rebuild 清表重建；默认增量
6. 结束打印统计行

【约束】
- 写表前校验 embedding 实际维度与表定义一致
- 只导入 data/raw/；data/local/ 是私有目录
- 中文全文检索要能正确分词
```

### Qoder 完成的工作

1. **文档解析**：解析 YAML front matter，提取元数据
2. **切片逻辑**：按 `##` 切分，每节 400-700 字
3. **向量化**：调用 DashScope API，1024 维嵌入
4. **建表**：创建 chunks 表，含向量和全文索引
5. **幂等设计**：按 doc_id 先删后插，chunk_uid 用 sha1

### 关键产出

- `app/ingest.py`：236 行数据管道脚本
- `app/embed.py`：向量化模块（支持 DashScope 和离线 IDF 哈希）

## 踩坑记录

**问题 1**：全文检索查不到中文

**原因**：用了 `IN BOOLEAN MODE`，中文 ngram 必须用自然语言模式

**Qoder 处理**：
1. 实测发现 `MATCH(content) AGAINST('伪共享' IN BOOLEAN MODE)` 返回 0
2. Qoder 分析：布尔模式不会把查询串切成 bigram
3. 改为自然语言模式：`MATCH(content) AGAINST('伪共享')`
4. 验证命中数 > 0

**问题 2**：`content_seg` 预分词列多余

**原因**：ngram 分词器直接作用于原文即可，预分词是双重分词

**Qoder 处理**：
1. 实测 `TOKENIZE('伪共享指两个线程','ngram')` 返回正确 bigram
2. 取消 `content_seg` 列，直接用 `content` 建全文索引
3. 简化 ingest 逻辑，少一处不一致的实现

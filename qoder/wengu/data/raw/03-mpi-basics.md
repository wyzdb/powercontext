# MPI 点对点通信

## 通信子与秩

MPI 程序启动时，`mpiexec -n p` 拉起 p 个**独立进程**，每个进程跑同一份代码（SPMD 模型）。它们不共享内存，只能靠消息通信。

**通信子**（communicator）是一组进程的句柄，同时携带一个独立的编号空间。`MPI_COMM_WORLD` 包含所有进程。

**秩**（rank）是进程在通信子内的编号，从 0 到 p−1。`MPI_Comm_rank` 取自己的秩，`MPI_Comm_size` 取总数。程序几乎所有分支判断都写成 `if (rank == 0)` 这种形式。

通信子的价值在于**分组**：把 1000 个进程按行切成 10 个通信子，每行内部用 `MPI_Comm_split` 建一个新通信子，行内通信的秩就从 0 重新开始。这样同一份代码既能做行内归约，也能做列内归约，不必手工换算全局秩。用 `MPI_COMM_WORLD` 硬编码全局秩去模拟分组，是 MPI 代码最常见的可维护性灾难。

两个必须记住的约束：`MPI_Init` 之前、`MPI_Finalize` 之后，都不能调用其他 MPI 函数。`MPI_Comm_rank` 的第一个参数是通信子，传错通信子会拿到错误的秩，症状是程序跑得通但结果周期性错乱。

## 点对点通信与消息匹配

`MPI_Send(buf, count, datatype, dest, tag, comm)` 和 `MPI_Recv(buf, count, datatype, src, tag, comm, status)`。

一条消息能被正确接收，要同时满足**四项匹配**：通信子相同、源/目的对应、tag 相同、以及类型兼容。前三项不满足，接收方会一直等下去——**不报错，直接挂死**。

第四条「类型兼容」容易被忽略：MPI 不在类型不同但字节数相同（比如 MPI_INT 和 MPI_FLOAT 都是 4 字节）时自动转换。它要求 `recv_type == send_type` 且 `recv_buf_sz ≥ send_buf_sz`。这样设计是为了可移植性——不同平台上类型宽度未必一致，自动转换会埋下跨平台错误。

如果接收缓冲区开小了，`MPI_Recv` 会**截断**消息，多余部分被丢弃且不报错。要检测这种情况，用 `MPI_Get_count(&status, datatype, &n)` 拿到实际收到的元素个数，再和缓冲区容量比较。

`MPI_Send` 的语义还分两种：**标准模式**下，消息小于某个阈值时被缓冲、立即返回；超过阈值则阻塞到接收方取走。这个阈值由实现决定，代码不能依赖它——同一段程序在小消息下正常、大消息下挂死，通常就是踩了这个坑。要确定性行为，就用 `MPI_Ssend`（同步发送，一定等到对方开始接收）或 `MPI_Bsend`（显式缓冲，缓冲区自己管）。

## 死锁的四种典型成因

**1. 环形等待。** 所有进程先 `MPI_Send` 给下一个、再 `MPI_Recv` 上一个。小消息时靠缓冲侥幸通过，消息一大全部卡住。修法：让偶数号先发后收、奇数号先收后发，破坏环路；或者统一改用 `MPI_Sendrecv`，它原子地完成「发且收」。

**2. 缓冲区耗尽。** 一对多通信里，0 号进程连发 100 条给 1 号，而 1 号还没开始收。发送端缓冲塞满后阻塞，双方互等。修法：加流控（收到确认再发下一条），或者改成非阻塞 + 定期 `MPI_Wait`。

**3. 集合通信顺序不一致。** 进程 0 调 `MPI_Bcast`，进程 1 调 `MPI_Reduce`。两者都以为自己会等对方，实际谁也没等到对的人。这类 bug 最难查，因为挂死位置和真正的错误位置无关。修法：所有进程走完全相同的集合通信序列，用同一个条件判断是否参与。

**4. 非阻塞请求忘了等。** 调了 `MPI_Isend` 却没 `MPI_Wait`，缓冲区被下一轮覆盖，收到的是脏数据。这类不是死锁而是**数据损坏**，更难发现。

排查手段：`mpiexec` 挂住时用 `gdb -p` 附加到某个进程看栈，或者打开 MPI 实现的调试开关（OpenMPI 的 `--mca mpi_abort_print_stack 1`）。更土但有效的办法是在每次通信前后打带秩的日志，看谁最后一条日志后面没动静。

## 非阻塞通信与计算通信重叠

非阻塞调用的形式是「发起 + 等待」两步：

```c
MPI_Request req;
MPI_Isend(buf, n, MPI_DOUBLE, 1, 0, comm, &req);
/* ... 中间可以干别的 ... */
MPI_Wait(&req, MPI_STATUS_IGNORE);
```

它真正的价值不是「不阻塞」，而是**把通信藏在计算后面**。典型用法是分块流水线：

```c
for (int b = 0; b < nblocks; b++) {
    MPI_Irecv(halo[b], ..., MPI_ANY_SOURCE, TAG, comm, &req[b]);
}
for (int b = 0; b < nblocks; b++) {
    compute_interior(b);          /* 算内部，不依赖 halo */
    MPI_Wait(&req[b], MPI_STATUS_IGNORE);
    compute_boundary(b);          /* 再算边界 */
}
```

这样网络传输和浮点运算在时间上重叠，总时间取两者较大值而不是相加。

三个必须遵守的规则：

1. **请求必须等。** 每个 `MPI_Irecv`/`MPI_Isend` 都要有对应的 `MPI_Wait` 或 `MPI_Test`，否则程序结束时资源泄漏，或者缓冲区被提前复用。
2. **等待前不能改缓冲区。** 非阻塞发送在 `MPI_Wait` 返回前，缓冲区内容必须视为「别人的」。想复用同一块内存，就得等。
3. **不要一次开太多请求。** 每个未完成的请求都要占资源，几千个同时挂着会拖垮实现。实践中按批（比如 32 或 64 个）发起和回收。

判断是否值得改用非阻塞：先测通信时间占比。如果一次迭代里通信不到总时间的 5%，改非阻塞大概只能拿回 2%，不如去优化内层循环。

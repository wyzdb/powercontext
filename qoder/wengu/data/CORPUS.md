## 为什么用自编语料

公开课件、教材节选这类材料，在「能不能随仓库分发」这件事上通常过不了关：

1. **权利归属不清**。课程材料往往由授课方编写，题库、习题解析的再分发需要授权。
2. **许可不明**。多数在线教材没有明确的再分发条款，默认按「保留所有权利」处理。
3. **可能夹带他人内容**。个人整理的学习资料里，往往混着教师给的题目、他人整理的笔记。

个人资料还有另一层问题：文件属性、正文页眉、甚至是命名习惯，都可能带出身份信息，而 git 历史一旦推送就收不回来。

自编语料把这几条一次性消除：内容自有、许可清晰、不含任何第三方文本与个人信息。

## 许可

本语料由本项目原创编写，以 **CC BY 4.0** 发布，可自由复制、修改、再分发（保留署名）。

不含任何第三方文本、图片或数据。文中引用的 API 名称（`MPI_Send`、`MPI_Allreduce`、`omp parallel for` 等）属于各自标准的公开接口约定。

## 结构约定

每篇都是「YAML front matter + 若干 `##` 小节」：

```markdown
---
doc_id: 03-mpi-basics
title: MPI 点对点通信
doc_type: 讲义
course: parallel-computing
language: zh
sections: 4
---

# MPI 点对点通信

## 通信子与秩
...正文...

## 点对点通信与消息匹配
...正文...
```

**每个 `##` 小节就是天然的切片单元**——400 到 700 字，正好落在切块目标区间，出处可以直接定位到「哪个文件第几节」。这是故意设计的，让「引用溯源」这个功能有干净的落点。

## 怎么替换成你自己的资料

把任意 markdown 丢进 `data/raw/`，保持同样的 front matter，然后：

```bash
python scripts/build_manifest.py
```

代码不需要改。切片逻辑按 `##` 走，所以资料有多少篇、多少节都不影响。

如果资料是 PDF 或 Word，先转成 markdown 再放进来——转换质量直接决定检索效果，别把糊成一坨的文本塞进来。

## 隐私自检

`scripts/build_manifest.py` 在生成清单的同时会扫一遍语料，命中以下任意一类就返回非零并拒绝写文件：

- 11 位以上的连续数字（疑似学号、手机号）
- 邮箱地址
- `姓名：` / `学号：` / `指导教师：` / `班级：` 这类表单字段
- `C:\Users\` 这类本机绝对路径

这道检查是给「以后往语料里加东西」的人准备的，防止手滑把带身份信息的材料提交上去。CI 里可以直接挂 `python scripts/build_manifest.py --check`。

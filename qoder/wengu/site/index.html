解决什么问题

整理文献要翻几十篇论文，复习时找不到上学期的笔记，周报总要从聊天记录里一条条拼。学习、科研和工作中，总有一些重复又耗时的环节值得被改造。

温故针对的是「课程资料复习」这个具体场景：你有 6 篇并行计算讲义，考前三天想高效复习，但翻找、记忆、自我检测都很低效。

痛点 1：找得到，但不知道重点

23 节内容里任何一节都可能考，判断依据在脑子里，不在资料里。全局搜索能命中，但命中太多等于没命中。

痛点 2：错了没人记

做错一道题，心里记一下「这个我错了」。下次还是错同一类，因为没有东西提醒你哪里薄弱。

痛点 3：不知道从哪开始

剩三天，六篇，先看哪篇？凭感觉抽一篇，往往不是最该看的那篇。复习没有优先级。

核心功能

1

带出处的混合检索

输入问题，系统从讲义中检索最相关的段落，每条结果都带精确出处（文件名 + 章节标题）。检索结合向量语义、全文关键词和标量过滤，一条 SQL 完成融合排序。资料里没有的内容，系统会明确说「资料中未提及」，不编造答案。

2

弱点驱动的出题与判分

系统根据你的薄弱知识点出题，而不是随机抽题。答错会记进弱点档案，答对会推进掌握进度。出题依据来自讲义原文，判分由 LLM 完成并给出理由。整个过程可追溯、可核对。

3

跨会话的学习者记忆

每个学习者有独立的记忆档案，记录薄弱概念、掌握进度和复习偏好。记忆存在 PowerContext 里，跨会话持久化。下次打开应用，系统知道你是谁、哪里不会、该从哪开始。

4

今日复习清单

根据弱点档案生成个性化复习计划：3 个概念 + 3 道题，预计 15 分钟完成。优先复习「学过但反复错」的内容，已掌握的概念自动移出清单。复习有优先级，时间不浪费。

技术架构

温故的技术分工非常清晰：seekdb 记得「资料说了什么」，PowerContext 记得「你哪里不会」。两者互斥且互补，没有模糊地带。

┌─────────────┐
│   前端 UI   │  web/index.html（单页，纯 HTML+fetch）
└──────┬──────┘
       │
       ▼
┌─────────────┐      ┌──────────────┐      ┌─────────────┐
│  FastAPI    │─────▶│   seekdb     │      │ PowerContext│
│  应用层     │      │  （数据存储） │      │ （记忆存储）│
└──────┬──────┘      └──────────────┘      └─────────────┘
       │
       │  读取
       ▼
┌─────────────┐
│  9 张表     │  kb_meta, doc_meta, chunks, concept,
│             │  chunk_concept, concept_edge, quiz_item,
│             │  qa_log, quiz_attempt
└─────────────┘

数据流：
  提问 → POST /api/ask → seekdb 混合检索 → 返回带出处的引用
  出题 → GET /api/quiz → seekdb 取依据 → LLM 生成题目
  判分 → POST /api/grade → LLM 判定 → PowerContext 写回弱点
  档案 → GET /api/profile → PowerContext 读弱点 → 生成复习计划

seekdb 的角色

seekdb 是唯一的数据存储，负责：

  • 存储 6 篇讲义的 23 个切片，每个切片带 1024 维向量嵌入
  • 建立向量索引（HNSW，L2 距离）和全文索引（ngram 分词器）
  • 在一条 SQL 内完成向量检索 + 全文匹配 + 标量过滤，用 RRF 融合排序
  • 存储概念词表（40 个受控概念）、概念关系、题目、答题记录、查询日志

seekdb 不存：用户弱点、进度、偏好。这些是 PowerContext 的事。

PowerContext 的角色

PowerContext 是唯一的记忆存储，负责：

  • 每个学习者一个 scope，存储 weakness / progress / preference 三类记忆
  • 支持跨会话持久化：关闭应用再打开，记忆仍在
  • 提供记忆的读写 API：remember、entries/list、context/prepare

PowerContext 不存：文档正文、向量、检索结果。这些是 seekdb 的事。

技术栈明细

组件 技术选型 版本 / 配置
数据存储 seekdb（OceanBase MySQL 兼容） Docker oceanbase/seekdb:latest，端口 2881
记忆存储 PowerContext HTTP API http://127.0.0.1:8000
向量嵌入 DashScope text-embedding-v3 1024 维，离线 IDF 哈希兜底
对话模型 Qwen-plus（百炼 API） 用于出题、判分、讲解

开发工具 Qoder 全部开发工作由 Qoder 完成

快速开始

从零到跑通，只需四步。所有命令都在 qoder/wengu/ 目录下执行。

步骤 1：启动 seekdb

docker run -d --name seekdb \
  -p 2881:2881 -p 2886:2886 \
  -v ./data/seekdb:/var/lib/oceanbase \
  oceanbase/seekdb:latest

等待容器启动完成（约 30 秒），可以用 docker logs seekdb 查看日志。

步骤 2：安装依赖

pip install -r requirements.txt -i https://pypi.tuna.tsinghua.edu.cn/simple

依赖很轻：只有 pymysql、fastapi、uvicorn 三个包。

步骤 3：初始化数据库并导入语料

# 建库建表
python scripts/init_db.py

# 导入 6 篇讲义（23 节 / 40 个概念）
python -m app.ingest

预期输出：入库完成：chunks=23 concept=40

步骤 4：启动服务

python -m uvicorn app.main:app --port 8080

浏览器打开 http://127.0.0.1:8080，开始使用。

一键脚本：也可以直接运行 bash scripts/init_demo.sh，自动完成上述所有步骤。

验证样例

以下四个样例覆盖核心功能，可以按步骤复现。

V1 · 混合检索命中

  • 输入：在提问框输入「非阻塞通信会造成死锁吗」
  • 操作：点击「检索」
  • 预期：返回 3 条引用卡片，第 1 条出处是《MPI 点对点通信》>> 死锁的四种典型成因
  • 技术作用：一条 SQL 内完成向量（l2_distance ... APPROXIMATE）+ 全文（MATCH ... AGAINST）+ 标量过滤，RRF 融合排序
  • 实测延迟：100–500 ms

V2 · 拒绝编造（负向验证）

  • 输入：「红烧肉怎么做好吃」
  • 预期：回答「资料中未提及」，不返回任何引用
  • 判据：查询 bigram 覆盖率低于 0.25 时判 no_evidence
  • 实测：覆盖率 0.0，三条无关问题（红烧肉 / 量子退火 / 股市）全部正确拒绝

V3 · 出题与判分

  • 操作：出题区填「伪共享」→ 点击「出题」→ 等待 5–10 秒
  • 预期：生成一道简答题，状态行显示出处与「模型生成」
  • 操作：写下答案 → 点击「提交判分」
  • 预期：显示 ✅/❌ 与理由；答错时尝试写入记忆
  • 技术作用：/api/quiz 返回 llm_used=true；/api/grade 判定与理由一致；答错后 PowerContext 条目数 +1

V4 · 跨会话记忆

  • 操作：对 learner=demo 连续答错「伪共享」3 次
  • 预期：profile 里该概念 count=3、status 回到「新学」
  • 操作：关闭应用，重新启动
  • 预期：再次查看 profile，弱点记录仍在，证明记忆持久化到 PowerContext
  • 技术作用：记忆存在 PowerContext 的 scope 里，不依赖应用进程

Qoder 开发实践

温故的全部开发工作由 Qoder 完成，采用「八轮迭代」的开发模式。每轮有明确目标、验收标准和 commit，开发过程可追溯、可核对。

八轮开发脚本

  1. 第 1 轮 · 需求拆解：产出 docs/01-需求与方案.md，确定数据模型和技术分工
  2. 第 2 轮 · 连通性验证：产出 scripts/smoke_test.py，证明 seekdb 和 PowerContext 都能连上
  3. 第 3 轮 · 数据管道：产出 app/ingest.py，把 markdown 讲义变成可检索的库
  4. 第 4 轮 · 混合检索：产出 app/retrieval.py，一条 SQL 完成向量+全文+标量融合
  5. 第 5 轮 · 记忆层：产出 app/memory.py，实现 PowerContext 客户端和跨会话记忆
  6. 第 6 轮 · 应用层：产出 app/main.py 和 web/index.html，FastAPI + 单页前端
  7. 第 7 轮 · 复习闭环：把 seekdb 和 PowerContext 真正咬合起来，出题由记忆决定，依据由检索提供
  8. 第 8 轮 · 交付打包：异常矩阵、测试、一键启动脚本、验证样例文档

开发记录

每轮开发都有 Qoder 对话截图、commit 记录和验收证据，存放在 evidence/ 目录下。完整的提示词脚本见 docs/00-Qoder提示词脚本.md。

Qoder 的价值：八轮迭代让开发过程高度结构化。每轮只做一件事，验收标准明确，遇到问题把报错原文贴回 Qoder 让它分析而不是自己偷偷改。这种「报错 → 分析 → 修复」的往返，是判断「真用了 Qoder」最硬的证据。

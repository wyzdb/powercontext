### SPEC-ORD-004/R1 参数形态（订单列表按创建时间筛选 v1，proposed，必需）
来源：specs/SPEC-ORD-004-created-after.md:12-14

`GET /orders` 新增可选查询参数 `created_after`，取值为 ISO-8601 日历日期，格式固定为 `YYYY-MM-DD`。参数缺省时行为与当前版本一致；参数出现且非空时进入 R2 的过滤逻辑。`created_after` 以原始字符串从 HTTP 层传入服务层，由服务层解析与校验；HTTP 层只做参数透传，不得假设调用方会传入日期对象。

### SPEC-ORD-004/R2 过滤语义（订单列表按创建时间筛选 v1，proposed，必需）
来源：specs/SPEC-ORD-004-created-after.md:16-18

过滤条件是 `created_at` 的日期部分大于等于 `created_after`，比较按日历日进行，不受时区偏移影响。边界当天的订单必须全部包含：`00:00:00` 与 `23:59:59` 的订单都算命中，边界前一天 `23:59:59` 的订单必须排除。数据契约：`Order.created_at` 是 ISO-8601 **字符串**（例如 `2026-09-15T00:00:00+08:00`），不是 `date` 或 `datetime` 对象，实现不得调用其 `.date()` 一类方法。

### SPEC-ORD-004/R3 非法输入（订单列表按创建时间筛选 v1，proposed，必需）
来源：specs/SPEC-ORD-004-created-after.md:20-22

`created_after` 无法按 `YYYY-MM-DD` 解析时（例如 `2026-13-01`、`2026-9-1`、空值、非日期文本），接口返回 HTTP 400，响应体 `error.code` 为 `invalid_created_after`，并沿用 SPEC-API-001 的错误信封。

### SPEC-ORD-004/R4 与既有筛选、分页的组合（订单列表按创建时间筛选 v1，proposed，必需）
来源：specs/SPEC-ORD-004-created-after.md:24-26

`created_after` 必须能和 `status`、`min_total`、`page`、`page_size` 同时使用：先做全部过滤，再排序，最后分页；`total` 与 `pages` 按过滤后的集合计算，不得按过滤前的集合计算。

### SPEC-API-001/R2 业务校验失败（订单查询接口契约 v6，active，约束）
来源：specs/SPEC-API-001-query-contract.md:16-18

过滤参数或分页参数非法时返回 400，响应体固定为 `{"error": {"code": "...", "message": "..."}}`，`code` 使用服务层抛出的错误码（如 `invalid_status`、`invalid_pagination`、`invalid_min_total`）。

### SPEC-ORD-001/R1 页码与页大小边界（订单列表分页 v4，active，约束）
来源：specs/SPEC-ORD-001-pagination.md:12-14

`page` 是 1 起始的页码，取值必须大于等于 1；`page_size` 取值必须在 `1..100` 闭区间内，默认 20。非整数或越界时抛出 `invalid_pagination`，HTTP 层映射为 400。

### SPEC-ORD-001/R2 total 与 pages 的语义（订单列表分页 v4，active，约束）
来源：specs/SPEC-ORD-001-pagination.md:16-18

`total` 是过滤后的记录总数，`pages` 是 `ceil(total / page_size)`；两者都不能按过滤前的集合计算。响应必须回显调用方实际使用的 `page` 与 `page_size`。

### SPEC-ORD-002/R1 取值与错误码（订单状态筛选 v3，active，约束）
来源：specs/SPEC-ORD-002-status-filter.md:12-14

`status` 只接受 `pending`、`paid`、`shipped`、`cancelled` 四个取值；其他取值（包括拼写错误与空字符串）必须抛出 `invalid_status`，HTTP 层映射为 400，不得静默返回空列表。

### SPEC-ORD-003/R1 闭区间语义（订单金额下限筛选 v2，active，约束）
来源：specs/SPEC-ORD-003-min-total-filter.md:12-14

`min_total` 表示订单总额（单位：分）的下界，过滤条件为 `total_cents >= min_total`，等于下界的订单必须保留。

### SPEC-ORD-003/R2 非法取值（订单金额下限筛选 v2，active，约束）
来源：specs/SPEC-ORD-003-min-total-filter.md:16-18

`min_total` 必须是大于等于 0 的整数；负数、非整数文本抛出 `invalid_min_total`，HTTP 层映射为 400。

### SPEC-ORD-005/R1 排序键（订单列表稳定排序 v5，active，约束）
来源：specs/SPEC-ORD-005-stable-ordering.md:12-14

排序键是 `(-total_cents, id)`：总额从高到低；总额相同时按订单号字符串升序。排序必须稳定且与过滤条件无关，翻页前后不能出现同一订单重复或遗漏。
